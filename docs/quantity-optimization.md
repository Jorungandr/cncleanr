# 限定数量解析优化（未发布）

2026-10-09，`parse_cn_quantity()`，纯 R；不增加依赖、语法或接口。

原实现为每条输入逐一检查前缀、后缀和“余”中缀。
新实现按原始文本去重，然后批量匹配每条规则；解析后映射回完整输入。
不按归一化结果去重，避免把 `约1 2` 与 `约12` 混为一谈。
所有重复错误的原文、索引和原因仍逐条保留，strict 消息与基线一致。
代价是增加一个与输入长度相同的映射向量，不声称所有输入的内存占用都下降。

## 性能

Windows 11、R 4.6.1。基线为优化前 quantity 代码的独立安装库
`outputs/range-endpoint-optimization/library`。
初次对照 100000 个不同的 `约n万`：基线 6.70 秒，候选 1.66 秒，三次中位数，约 4 倍。
保存脚本复跑的不同值样本为基线 6.66 秒、候选 1.70 秒；完整等价性断言通过，进程退出码 0。

保存脚本的复跑中，100000 项、仅四种原文的重复样本：
基线 6.40 秒，候选平均每次 0.005 秒。
候选每轮连续调用 20 次再除以调用次数，三轮取中位数，避免计时分辨率产生“0 秒”。
这是特别适合去重的合成输入，不能宣传为所有数据都具有同样的加速倍数。
不混用不同轮次的耗时计算提速，也不以耗时阈值判断正确性。

复跑：

```powershell
Rscript --vanilla docs/quantity-performance.R outputs/range-endpoint-optimization/library
```

参数必须指向未优化的 quantity 基线库；脚本在独立环境加载工作区候选，不覆盖安装包。
