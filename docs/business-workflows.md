# 真实业务清洗：财务、薪资和统计

[English](business-workflows_EN.md)

这份教程验证“文本导入 → 按字段解析 → 分开复核 → 导出并读回”的完整流程。
脚本是项目外部审计工具，不增加 cncleanr 的六个公开函数。

## 1. 导入时保留文本和来源

```r
library(cncleanr)
cases <- read.csv("outputs/business-validation-2026-10-30/cases.csv",
  colClasses = "character", na.strings = character(),
  check.names = FALSE, fileEncoding = "UTF-8")
```

每个案例保留独立 `case_id`、原始 `record_id`、`source_row`、字段名、原文、
实际解析文本及转换说明。财报的 source_row 是原始答案记录行，片段与整段答案明确区分。
薪资的记录编号按来源行创建，不是职位业务主键；生产数据应优先保留自己的稳定 ID。

## 2. 按字段含义解析

```r
parse_cn_quantity("6.38%")
parse_cn_number("35000", unit = "元")
parse_cn_range("35000~45000")
```

财报片段保留限定词，不把“大于”当成精确值；39 个负数预期也已核对。
薪资区间由原始上下限两个字段明确构造，692 个有效区间是派生案例，不是原有中文区间。
只有两个端点均大于 0 且顺序正确时才构造闭区间；不能把 `0` 或 `-` 自动推断成无穷上限。
保留月薪、时薪、日薪、计件等计薪方式，不能直接比较或擅自乘工作小时数。

统计中的裸百分数必须根据字段元数据显式加 `%`；525 个百分比字段按 Decimal 除以 100
构造预期。另 525 个“千人”字段保持原单位，不能传 `unit="千元"`，也不自动换成人数。
观光金额列明确传 `unit="万元"`，与普通人数列分开处理。

## 3. 区分缺失、解析失败和业务复核

不要直接删除所有 NA 行。脚本分别处理：

- 普通缺失：没有问题记录的缺失值。
- 解析失败：保留 `cn_problems()` 返回的原因、原文及来源行号。
- 业务复核：308 个无法确定有效闭区间的薪资记录，先不调用区间解析器。

按学历／证照核薪的 77 条说明，以及带奖金、多个薪资数字或面议的两条完整岗位描述，
应当拒绝自动解释为单个数值区间。金额列的 `#VALUE!`、“未统计”、多项收益说明也应进入复核。
“正确拒绝”表示没有误给一个数字，不表示已经替用户完成业务解释。

## 4. 导出、读回和精度边界

脚本为每个场景分别输出 `*-cleaned.csv` 与 `*-review.csv`，并保留计薪周期、
源单位、限定词、上下界包含标志。读回时以文本读取，逐列检查原文和来源字段，
数值按每行相对容差 1e-12 比较。

`parsed-objects.rds` 保存分组解析对象及 case_id，读回必须与原对象完全一致，
包括诊断属性。CSV 不保存 R 属性，也不保证 double 尾数、负零或 NA/NaN 无损，
见 [CSV 保存边界](csv-cleaning.md#csv-不是无损的-r-对象备份)。
