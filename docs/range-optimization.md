## 对照结果

基线为已独立安装、未修改的 0.2.7；候选为当前工作区代码。
Windows 11、R 4.6.1，每项三次耗时的中位数。

| 输入 | 基线 | 候选 |
| --- | ---: | ---: |
| 10000 个不同的 `n万` 单值边界 | 1.29 秒 | 0.55 秒 |
| 100000 个不同的 `n万` 单值边界 | 未完成，长测已停止 | 5.76 秒 |

小规模样本约 2.3 倍提速。未将基线未完成的时间作量化结果，也不外推倍数。
这些是合成点区间，不是 100000 个带两个端点的真实范围。

随后运行保存的对照脚本，10000 项基线 2.66 秒、候选 0.64 秒，
100000 项候选 13.66 秒。两轮受负载、垃圾回收及函数加载状态影响，
不能把不同轮次的耗时混算或承诺固定倍数。
对照脚本的完整结果相等断言及独立数列断言通过，进程退出码 0。

`range-performance.R` 比较旧新版完整结果（包含问题属性），覆盖空输入、缺失、
因子、无穷数值、不同不等式、近似值、逆序区间、科学计数及 1000 个不同区间。
另以独立数列检查大批量点区间。

```powershell

```

参数必须指向未优化的基线库。时间会随机器及负载改变，不用耗时阈值决定测试通过。
开发说明已记录于 NEWS 的 unreleased 部分，版本号及已发布附件保持不变。

## 第二阶段：实际双端点区间

随后优化候选处理：一次检索分隔符，预分配候选数组，再按源输入分组有效候选。
按组位置访问，避免循环中按名称查找；不改变分隔符、端点继承或歧义判断规则。
初稿按名称查找的额外开销未获得理想收益，最终候选改为位置访问后再验证。

该阶段基线为 `outputs/range-optimization/library`，即第一阶段优化后的独立安装库，
不能将下表倍数与上一节相乘。候选为本阶段最终代码，三次耗时中位数：

| 输入 | 第一阶段基线 | 第二阶段候选 |
| --- | ---: | ---: |
| 10000 个不同的 `n-(n+1)万` 闭区间 | 4.48 秒 | 1.05 秒 |
| 20000 个不同的 `n-(n+1)万` 闭区间 | 4.92 秒 | 2.13 秒 |

分别约 4.3 倍和 2.3 倍；不同规模受负载和 GC 影响，不能推算更大规模的线性耗时。
完整范围 fixture 的候选/基线结果及问题属性一致；新增负数、科学计数法、
缺失端点、逆序和多分隔符的回归断言通过。
最终候选的安装、合成批量检查、16961 项公开数据审计及既有金融/科学/生物审计通过。
全部独立审计进程退出码为 0；testthat 断言虽通过，进程仍有已知的本地退出崩溃。
