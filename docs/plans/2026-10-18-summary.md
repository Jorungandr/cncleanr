# Diagnostic summary implementation plan

**Approved goal:** `cn_summary(x)` summarizes unmodified parser results or
`cn_subset()` results, without parsing source data again or changing parsers.
**Architecture:** base-R list with `counts` (one-row data frame: total, parsed,
missing, failed) and `reasons` (reason/count rows, first occurrence order).
No new class/print method/dependency, no C or parser-speed changes.

NA/NaN rows are missing unless their current positions occur in `problems`.
Numeric Inf/-Inf and textual open bounds are successful, not failures. Summary
reason counts reflect selected occurrences, including duplicated selections.
Empty inputs return one zero-count row and a typed empty reason table.

Reuse the existing result-shape/problem-index validation by extracting a private
`cn_result_problems()` used by `cn_subset()` and `cn_summary()`. Keep existing
subset rules; summary additionally validates column types and failed/missing
consistency before counting. Obvious malformed/stale attributes error, but plain
R result types cannot prove provenance or detect removed diagnostics. Document
that limitation; no automatic repair, source reparse or per-row status API.

Alternatives: return only a printed report (hard to reuse), or introduce result
classes and automatic tracking (unnecessary API change). Use ordinary tables.

1. Add tests in `tests/testthat/test-summary.R`: all parsers, literal expected
   counts/reasons, subsets/duplicates, empty/all-missing/all-failed, nonfinite
   numeric values, qualifier/range differences, malformed inputs, immutability
   and no parser calls. Run before implementation to demonstrate failure.
2. Implement shared metadata guard in `R/problems.R`, summary in `R/summary.R`;
   run focused and existing subset/system tests. No extra work during parsing.
3. Update NAMESPACE/Rd with roxygen, both READMEs and package overview, NEWS,
   version 0.2.19 and bilingual release notes. Extend existing release verifier
   with a summary smoke check. Run literal README audit including real units.
4. Commit/push clean source, build/check exact archive locally and on all five CI
   platforms; repeat real third-party/system/data audits. Publish fixed v0.2.19,
   unauthenticated public download/hash, isolated installation and full recheck.
5. Record exact evidence/limits and push; no CRAN submission.

Continue in the authorized checkout without agents or another session. The user
requested the complete GitHub workflow in one turn. Skip unrelated refactoring.
