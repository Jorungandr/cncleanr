# Explicit compound magnitudes implementation plan

Approved goal: parse explicit descending compound magnitudes such as
`1亿2000万`, qualified quantities and fully specified ranges; do not infer `3万5`.

Design: add a private vectorized R fallback called only for existing number
syntax failures. Two or three unsigned decimal/grouped-comma terms each have a
`万亿`, `亿` or `万` suffix, in strictly descending distinct order. Optional
currency prefix/suffix and one overall sign/accounting parentheses reuse the
existing rules. Per-term scientific notation, bare trailing values, internal
currency markers and interdigit whitespace grouping are outside this first
compound grammar. Existing single-term scientific/grouped syntax is unchanged.

Parse matched component terms in one call to the existing number parser with
`na=character()` and no header unit; those are single terms, so no compound
recursion. Sum up to three finite positive components, then apply the whole
sign. Preserve normal double limitations and reject component/sum overflow.
Whole-cell custom NA matching still precedes fallback. All header units conflict
with compounds rather than guessing an overall multiplier.

The quantity parser already strips qualifiers through number parsing. Reuse
range endpoint parsing too, but guard suffix propagation: if an endpoint is
compound, the opposite endpoint must specify a trailing unit explicitly,
including accounting parentheses. Reject ambiguous shared-unit cases rather
than extending the compound's final small unit to a bare endpoint.

Tasks:
1. Add `tests/testthat/test-compound.R`: literal golden values, currency/signs,
   fullwidth, grouping, qualifiers/bounds, ranges, malformed expressions,
   header conflicts, original diagnostics, NA, duplicates, factors and overflow.
   Demonstrate failures against installed 0.2.19 before production changes.
2. Implement `R/parse-cn-compound.R`; hook existing syntax-failure branch in
   `R/parse-cn-number.R`; prevent ambiguous compound range suffix propagation in
   `R/parse-cn-range.R`. Leave C and ordinary fast-path returns untouched.
3. Run full/native-reference tests, real third-party/system/data audits and
   same-process alternating old/new performance comparisons for ordinary cases.
   Add independent integer-arithmetic generated golden compound examples.
4. Update version 0.2.20, NEWS, bilingual README/Rd, release notes and verifier.
   Clean committed archive local check and five CI jobs; fixed tag/release,
   public unauthenticated download/hash, isolated installation and full recheck.
5. Record actual evidence and limitations; no CRAN submission or new runtime
   dependency. No new native-tool results claimed when C remains unchanged.

Alternative: full Chinese-number grammar or a new C parser. Deferred: the
approved explicit narrow syntax can reuse existing routines and fallback paths.
Use the existing authorized checkout; no delegated agents or extra sessions.
