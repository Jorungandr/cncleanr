# cncleanr 0.2.0 Quantity and Range Parsing Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Extend `cncleanr` from exact compact-number parsing to safe parsing of currency-prefixed values, qualified quantities, and numeric ranges, with bilingual project documentation.

**Architecture:** Keep `parse_cn_number()` as the strict scalar-vector foundation and add two structured parsers on top. `parse_cn_quantity()` returns values plus semantic qualifiers; `parse_cn_range()` returns explicit bounds instead of inventing a midpoint. All parsers use the same normalization, missing-value handling, and structured problem reporting.

**Tech Stack:** Base R, roxygen2 documentation, testthat 3, GitHub Actions.

**Files:**

### Task 3: Add qualified-quantity parsing

**Files:**
- Create: `R/parse-cn-quantity.R`
- Modify: `NAMESPACE`
- Create: `man/parse_cn_quantity.Rd`
- Create: `tests/testthat/test-parse-cn-quantity.R`
- Modify: `tests/parser.R`

**Steps:**
1. Add failing tests for exact, approximate, strict lower/upper, and inclusive lower/upper qualifiers.
2. Implement ordered qualifier recognition for forms such as `约3万`, `超过2亿`, `不少于5万`, and `10%以下`.
3. Return a base data frame with `value` and `qualifier`, and attach the shared problems schema when parsing fails.
4. Test strict mode, missing values, names, and conflicting qualifiers.

### Task 4: Add range parsing

**Files:**

- Create: `man/parse_cn_range.Rd`

**Steps:**

3. Propagate an unambiguous suffix across a range such as `3-5万`.
4. Reject reversed, conflicting, or unsupported ranges with structured problems.
