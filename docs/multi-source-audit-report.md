## 有代表性的边界

- `20%-30%` → 0.2 到 0.3；`17．65％～58．82％` → 0.1765 到 0.5882。
  区间应使用 `parse_cn_range()`，不能用单值函数截取其中一端。
- `31%±16%` 等八个出现次数的波动表达被拒绝；其中包含重复项。
  `±` 可能表示标准差、标准误等，不应擅自转换为确定上下界。
- `约15％左右`（一次）被判为重复限定词。日常语言很常见，但当前包
  采用保守策略；可以作为以后讨论容错规则的真实依据，不在这轮自动放宽。
- `20％～30％以上`（一次）混合了区间和开放限定，语义需要人工确认。
- 企鹅同位素列包含负小数。这里只验证裸数字和缺失值；列名中的
  `o/oo` 是千分比单位，包没有自动转换物理单位，也没有把它当成百分比。

## 方法与限制

Python 使用标准库 Decimal 计算预期值，R 使用已安装的发布包验证。
CSL 抽取先做一对一全角字符归一化来定位片段，再把原始片段交给包；
保留区间和 `±`，避免用一个看似有效的子串提高成功率。
结果含原记录位置、上下文、预期值、实际值和原因，保存在本地
`outputs/multi-source-audit/results.tsv`。

普通数值的容差为 `max(1, abs(expected)) * 1e-12`；科研区间端点容差
为 `1e-12`，限定词与边界开闭要求完全一致。
仅五个科研表达另作人工核对，未逐条人工标注所有抽取结果。
抽取规则不是包功能，不证明可以理解整段文本；语义标注来自词法规则，
也不证明论文、财报或工资等事实正确。未覆盖所有格式或所有业务领域。

结论：在已经分列或明确抽取的数字字段上，现有功能表现稳定；
这批样本没有发现已支持语法内的错误换算。新证据主要指向科研统计表达
和自然语言冗余限定的边界，不支持立即增加通用文本解析或 C 实现。

## 复现

在项目根目录创建 `outputs/multi-source-audit/`，下载下列固定版本文件：

- [CSL test.tsv](https://raw.githubusercontent.com/ydli-ai/CSL/0f1ac0626d584cd3c72f8be26d329eb4f967cfd0/benchmark/ts/test.tsv) → `csl.tsv`。
- [企鹅 penguins_raw.csv](https://raw.githubusercontent.com/allisonhorst/palmerpenguins/8957207b78d6ccd1b4654a9dd9c9041b657478ab/inst/extdata/penguins_raw.csv) → `penguins_raw.csv`。
- CFQA 下载与抽取步骤见 [此前报告](real-data-audit-report.md)，准备好
  `outputs/real-data-audit/spans.tsv`。

原始文件 SHA256：

- CSL：`51900a71a26193525e98fa4e65c0e78ea4ca0b84cd1f0da0de0690ffdb85791d`。
- 企鹅：`144f623143c9360fd77322a4f86acb06dc198814dbd2669724c63e6457b907bd`。

安装 GitHub 0.2.6 到独立库 `outputs/release-0.2.6/library`，然后执行：

```text
python docs/multi-source-audit.py
Rscript --vanilla docs/multi-source-audit.R
```

验收脚本只依赖 Python 标准库、R 基础函数和 cncleanr；不新增包依赖。
如果不使用独立库，请调整脚本开头的 `.libPaths()`。
